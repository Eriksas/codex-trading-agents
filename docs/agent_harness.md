# Agent Harness：让模型按规则参与研究

**Prompt** 是“告诉模型这次需要做什么”。**Agent Harness** 是“模型外面保证 Agent 能按规则完成任务的一套运行机制”。本项目由入口脚本、输入输出约定、错误处理、日志与人工规则共同组成，还不是统一的 Agent 平台。

可以把它想成分析任务的执行安排：模型拿哪些材料、哪些字段允许写、出错怎么办、结论由谁签字。

## 项目实际有哪些机制

| 环节 | 具体体现 | 实现程度 |
|---|---|---|
| 项目规则 | [AGENTS.md](../AGENTS.md)、[HERMES.md](../HERMES.md)定义不造数据、不自动晋级和证据要求 | 行为规范，不是访问控制系统 |
| 角色分工 | [main_v2.py](../main_v2.py)默认直调 Python，`--llm` 才启用综合观察；Hermes 使用诊断/反方/草案模式 | 有入口和角色约定，并非每个模块都是自主 Agent |
| 数据输入 | [Steward 脚本](../scripts/run_strategy_steward.sh)读取健康报告、复盘、台账等；必需文件缺失则退出 | 存在性检查已实现，不代表自动证明数据正确 |
| 结构化输出 | 综合观察返回状态 JSON；experiment 返回实验 JSON | 能解析状态/JSON，尚无完整自然语言事实校验 |
| 错误处理 | `main_v2.py` 对 LLM 超时、CLI 缺失等记录失败并使用模板兜底；Steward 非法 JSON 保存空实验与原始输出 | 代码中已有，格式正确不代表结论成立 |
| 日志和报告 | `main_v2.py` 写日志和流程摘要；Steward 保存 Prompt、报告或草案 | 文件留痕；普通文件和 Git 历史不是不可篡改系统 |
| 学习记录 | [strategy_learning.py](../src/strategy_learning.py)由确定性事实整理经验和门槛 | 更新经验文件，不是训练模型 |
| 独立实验 | [实验草案](../strategy_experiments/README.md)与[搜索登记](../research/strategy_search_202607.py)，留出段需显式解锁 | 能记录试验，不能阻止操作者重复看数据 |
| 人工确认 | 重要策略变化需独立实验、历史验证、反方检查和明确人工批准 | 规则约束；无审批服务、签名或自动晋级状态机 |
| 回滚 | [配置备份](../strategy_legacy_v1.json)、[旧代码](../archive/market_scanner_legacy_v1.py)、[回滚指南](rollback_guide.md) | 手动恢复依据；不是自动回滚，也不保证旧策略更有效 |
| 流程评测 | [eval/](../eval/README.md)检查固定案例、结构化回答和约束 | 本次新增离线检查，文字事实仍需人工评审 |

## 工具权限：如实说明缺口

Hermes 的“只读”是项目规则与运行 Prompt 的要求：模型不直接改文件，由外层脚本保存输出。当前调用带有 `--ignore-rules`，依赖拼入的 Prompt 约束，并未在仓库中实现操作系统级只读沙箱或工具白名单。

`main_v2.py --llm` 的旧调用包含 `--dangerously-skip-permissions`。Prompt 要求只回写并验证 `synthesis`，外层代码解析模型返回的状态，但没有完整比对其他字段是否改动。因此不能宣称“模型在技术上绝不可能修改其他文件/数值”。默认模板路径无需该 CLI；本次保留运行逻辑，未新增模型调用。

## 一次任务怎样被约束

1. Python 先计算复盘和健康指标，保留来源文件。
2. Steward 检查必需文件、组装输入，选择 daily/critic/experiment 模式。
3. Agent 输出有证据的候选解释或反方意见；草案不自动运行研究或修改主策略。
4. Python 研究脚本另行验证；失败、口径冲突和样本不足一并记入结论。
5. 人工决定继续观察、否决假设或批准独立实验。策略修改另行确认，保留恢复依据。

Eval 可以检查回答是否声明数据不足、是否越过晋级边界等字段，但没有模型执行权限控制，也不是人工确认的替代品。

**Prompt 决定模型如何理解任务；Harness 决定模型在什么环境、权限和规则下执行任务。** 本项目已有若干具体机制，同时保留需要人工负责的部分。
