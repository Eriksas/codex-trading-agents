# 分析方法

**AI 提出假设，程序验证结论。** 下面是一套研究组织方法，不是声称所有步骤已自动化。

## 1. 明确问题

不要只问“为什么策略不好？”，而应问：“收益下降主要来自触发率、胜率、盈亏比，还是特定市场阶段？”

开始前写清五件事：分析对象（哪条冻结规则）、时间范围、样本范围（哪些股票/事件）、核心指标、对照基准。还要约定何种结果会否决假设，避免看到结果后改标准。

例如：“对同一冻结规则，比较前后两段已平仓模拟记录的触发率和平均净收益；以同日期、相近风格的随机选股为对照。”这只是问题示例，不是新增实验结果。

## 2. 检查数据

| 检查项 | 做法与已有依据 |
|---|---|
| 缺失、重复、时间覆盖 | [数据扩展脚本](../research/data_expansion_pipeline.py)的 `_quality_metrics` 检查字段缺失、交易日期覆盖和重复；先看数据源及覆盖报告 |
| 数据口径 | 核对复权/原始价格、费用、事件级/组合级收益、股票池与时变 ST；[V3 重审](v3_reaudit_2026-07-03.md)说明错误指数能改变判断 |
| 未来数据泄漏 | 检查信号只使用当时可用数据、次日成交、时间切分；[面板回测器](../research/panel_backtester.py)实现执行时序，但不存在一键证明所有研究无泄漏的检查器 |
| 样本量 | 同时列日期数、事件数、逐笔交易数；同一天买十只股票不等于十次独立市场事件 |
| 数据源不一致 | 用重叠日期核对来源；无法解释的差异先阻断相关结论，不让 Agent 猜哪个数字正确 |

缺失要标记不足，不允许 Agent 生成行情来填洞。已有[因子预处理](../research/factor_research.py)包含当日横截面中位数填充等确定性处理，这是一项需要披露的口径，不能说仓库“从不填充任何字段”。它不能替代缺失行情或证明原始数据完整。

## 3. 指标拆解

```text
策略收益变化
├─ 触发次数 / 触发率
├─ 胜率
├─ 单次平均净收益
├─ 止损率
├─ 盈亏比
└─ 市场环境与仓位暴露结构
```

这是一棵诊断问题树，不是可直接相加的收益恒等式。胜率、盈亏比和平均收益相互关联；资金占用、重叠持仓、费用也会改变组合结果。

[健康监控](../src/strategy_health.py)已有 5/20/60 日窗口、标签和市场环境拆解。窗口由日期差计算，不能一概称为“交易日窗口”；已有指标以输出字段为准。盈亏比等额外问题需从逐笔数据另行计算，不能假设健康报告已经包含。

按时间阶段、市场环境、波动率、流动性或股票特征进一步切片。比较前说明每组分母、样本是否重叠、空组如何处理；没有行业数据时不能捏造行业归因。

## 4. Agent 提出候选假设

Agent 列出待检验解释，不直接宣布原因。每项假设写清：

- 假设是什么；例如“高波动股票可能拖累表现”。
- 支持证据：来源文件、日期、指标、样本量。
- 反对证据：反例、其他时间段、可能混杂的股票特征。
- 还需要做什么分析：脚本、对照组、指标和失败条件。
- 当前置信程度：低/中/高及理由；不是未经校准的概率。

缺证据就写“未知”。现有 [Steward Prompt](../prompts/strategy_steward_agent.md)承接诊断和候选草案，critic 模式再找反例；不为角色命名额外启动多个 Agent。

## 5. Python 定量验证

**Agent 负责辅助提出分析方向，Python 负责关键数值计算。**

| 方法 | 回答的问题 | 现有入口 |
|---|---|---|
| 分组分析 | 高低因子组表现是否不同 | [factor_research.py](../research/factor_research.py) |
| IC / RankIC | 因子值/排名和后续收益是否相关 | 同上；按日期横截面计算，注意最小样本 |
| 因子相关性 | 多个指标是否重复表达相同信息 | 同上；不据此宣布因果关系 |
| 消融实验 | 去掉一个条件后结果是否变化 | 同上及[研究说明](factor_research.md) |
| 时间、环境切片 | 结果是否依赖某一阶段 | [扩展回测](../research/backtest_v3_expanded.py)、[第三轮研究](../research/factor_research_round3.py) |
| 冻结与长样本复检 | 原规则能否在更多数据上维持 | [冻结验证](../research/factor_research_freeze_v3.py)、[搜索脚本](../research/strategy_search_202607.py) |

保留配置、数据范围、命令和结果文件。程序与文字矛盾时先检查单位、日期及口径；确认同一口径后修正文案。若怀疑程序或数据错误，记录问题并重算，不能选择更好看的数字。

## 6. 反方检查

看到“高波动组更差”，继续检查：是否只由一段时间贡献？样本是否太少？是否受行业/流动性影响？是否泄漏未来信息？费用加压后是否成立？只是相关，还是有足够对照支持的机制解释？

反方意见同样需要证据，不能靠措辞否定 Python 结果。[真实案例](case_study_strategy_diagnosis.md)展示同日随机选股与随机日期对照如何拆开“选股”和“择时”解释。

独立实验需写清基线、只改变什么、主要指标、时间区间、失败条件和已试配置数量。被冻结规则以外的改动另立实验。看过结果的样本不能重新包装成从未使用的样本外数据。

## 7. 结论分级

本次统一新分析记录的用语，不回填或改写历史报告原状态：

| 标记 | 中文含义 | 下一步 |
|---|---|---|
| Rejected | 证据明显不支持，或未通过事先约定的主要标准 | 否决该项主张，保留失败原因 |
| Inconclusive | 样本不足或证据冲突 | 标明还缺什么，继续记录 |
| Promising | 存在初步支持，仍需独立验证 | 进入实验建议，不晋级主策略 |
| Validated | 在明确范围内通过预先设定的主要验证 | 仍需披露限制并交人工决定，不等于未来有效 |

分级是报告规范和最小 Eval 字段，不是主策略里的自动状态机。项目没有据此宣称大量 Validated 策略。样本下限以各协议为准：健康监控的 10 笔提示、V3 的 30–50 笔观察目标、bounce 的 20 次事件、gate 的 Day250 不能互相替代；达到数量也不等于自动通过。
