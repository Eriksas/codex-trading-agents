# 第一阶段：统一诊断入口

## 目标与实现

新读者只需 `python main.py demo`，打开一份报告，即可理解数据、程序、AI 和人工分别负责什么。实际数据沿用 `python main.py diagnose --date YYYY-MM-DD`。

新增 [main.py](../main.py) 和 [diagnosis.py](../src/diagnosis.py)，复用 [strategy_health.py](../src/strategy_health.py) 的现有计算。原始输入先校验并复制到临时快照，再由原函数计算，输入哈希对应实际快照。程序输出与 AI 返回文字分别保存；只有匹配同一事实包的回答才允许导入。

运行产物全部位于忽略的 `output/diagnosis/`，每次独立目录。没有将扫描、回测、台账重写为新的框架。规则参数与指标分母沿用健康统计模块，诊断不设置策略晋级状态。

## 兼容边界

- 原 `main_v2.py`、扫描器、V3 日报、前向观察、运行脚本与定时任务保持原行为。
- 新主入口不导入研究轮次，也不加载行情或模型 SDK，只需 Python 标准库。
- 未移动历史研究代码和数据；研究与文档目录通过导航区分日常使用、工具和历史。
- 新报告是诊断与审核入口，`python/` 子目录保留原健康模块详细产物。
- 共享 Steward 规则不变，新入口在生成任务时补充专用返回契约；旧 Hermes experiment JSON 不变。

## 已知限制

健康统计是描述性汇总，不是策略有效性检验。当前按提供目录聚合，没有自动识别多策略混用、完整交易日覆盖或跨数据源口径。使用者负责选择一致的数据集。

本轮 AI 路径是生成任务材料、人工采集并导入候选假设与反方意见，尚未自动调用模型。匹配哈希和结构检查不能证明文字真实，人工核对不可省略。已有最小 Eval 独立保留，不冒称已完成端到端模型评测。
